Advanced

Every feature explained.

Full walkthrough of providers, typing, emit/ack, lifecycle, namespaces, runtime config, SSR, and testing — with copy-ready snippets under each topic.

1. Providers and DI

Register Socket.IO once at application bootstrap. The library wires SocketIoService, config tokens, and an overridable client factory into Angular DI.

  • provideSocketIo(config) — default unnamed socket for inject(SocketIoService) / injectSocketIo().
  • provideSocketIo(name, config) — named instance; inject with injectSocketIo('chat'). Use when chat and notifications use different hosts or namespaces.
  • SocketIoModule.forRoot / forFeature — same model for NgModule apps.
  • injectSocketIo<Listen, Emit>() — typed helper; optional name argument.

2. SocketIoConfig

Configuration is a thin Angular wrapper around the official client. Unknown option keys still pass through to socket.io-client.

  • url — scheme + host[:port]. Trailing slashes are stripped.
  • namespace — e.g. /chat. Appended correctly; do not put the namespace in url when using this field (and do not confuse it with Engine.IO path).
  • autoConnect — default true in the browser. Set false for login-gated or playground-style Connect buttons. Ignored during SSR (nothing connects on the server).
  • options — auth, transports, reconnection, timeout, path, query, withCredentials, forceNew, closeOnBeforeunload, Node TLS fields, etc.

3. Strongly typed events

Mirror Socket.IO’s event-map pattern. Listen maps describe server→client handlers; emit maps describe client→server handlers (including optional ack callbacks).

  • Wrong event names fail TypeScript where possible.
  • Payload shapes are checked on emit / fromEvent.
  • Ack argument types flow into emitWithAck result types.

4. Connection control

When autoConnect is false (or after logout), drive the socket explicitly. The service instance stays alive across disconnect/connect so you do not lose DI wiring.

  • connect / open — start connecting; safe if already connected.
  • disconnect / close — close the transport; call connect again later.
  • isConnected() — imperative boolean. Prefer the connected Signal in templates.
  • With autoConnect: true, emit will nudge an inactive client to reconnect so payloads are not silently dropped.

5. Emit, acknowledgements, and timeouts

Fire-and-forget emits use emit. When the server replies with an ack callback, prefer Promise-based helpers instead of nesting callbacks.

  • emit(event, …args) — typed outbound event.
  • emitWithAck(event, …args) — returns a Promise that resolves with the server acknowledgement.
  • timeout(ms) — returns {{ '{ emit, emitWithAck }' }} bound to that deadline; ack Promises reject if the server is too slow.

6. Listening to events

Listeners are Observables so they compose with RxJS and Angular’s takeUntilDestroyed / async pipe.

  • fromEvent / on — shared stream; one native listener; removed when the last subscriber unsubscribes (share({{ '{' }} resetOnRefCountZero: true {{ '}' }})).
  • once — first matching event, then completes.
  • off / removeAllListeners — drop tracked streams and native listeners.
  • After recreateSocket, active fromEvent subscriptions re-attach to the new client automatically.
  • fromEvent('connect') / once('connect') replay when already connected (same idea as connect$).

7. Lifecycle Signals and streams

Connection UI should read Signals. Side effects and joins should subscribe to Observables. Both stay in sync — Observables are mirrors of the Signals via toObservable.

  • connected — whether the socket is currently connected.
  • recovered — Socket.IO connection state recovery succeeded on the last connect.
  • connectionState — disconnected | connecting | connected | reconnecting | error.
  • connect$ — emits on every successful connect and immediately for late subscribers if already connected (so joinRoom is not missed).
  • disconnect$ / connectError$ / error$ — transport and handshake failures.
  • reconnectAttempt$ / reconnect$ / reconnectError$ / reconnectFailed$ — Manager-level reconnection lifecycle.

8. Authentication

Credentials go in Socket.IO auth (handshake), not in ad-hoc query strings unless your server requires that.

  • options.auth at provide time for known tokens.
  • setAuth(auth) — update credentials for the next (re)connect.
  • authenticateAndConnect(auth) — set auth and (re)connect in one step after async login.
  • Never log auth payloads. Prefer short-lived tokens.

9. Namespaces and multiple sockets

Two patterns: separate DI registrations (different URLs or long-lived endpoints), or of(namespace) to fork a namespace from an existing service.

  • Named provideSocketIo — true multi-socket; each has its own service and lifecycle.
  • of('/admin') — returns a SocketIoService scoped to that namespace (cached per parent).
  • Namespace ≠ Engine.IO path. Path stays in options.path (default /socket.io).

10. Runtime config and recreate

When the URL, region, or auth is only known after bootstrap (tenant switch, feature flag), update config without tearing down the whole Angular app.

  • updateConfig(partial, { reconnect }) — merges URL / namespace / options. Default reconnect: true recreates and connects.
  • recreateSocket(autoConnect?) — tear down the native client and build a fresh one with the current config.
  • getConfig() — read-only snapshot for debugging or UI.

11. Native client escape hatch

Most apps never need this. When you must call a Socket.IO API that is not wrapped yet, use getSocket().

  • Returns the official socket.io-client instance.
  • Throws during SSR or after the service is destroyed.
  • Prefer library methods when they exist so typing and lifecycle stay consistent.

12. SSR and prerender

Socket.IO needs browser networking. The library uses isPlatformBrowser so Universal / prerender builds do not hang or open sockets on the server.

  • No client is created during SSR.
  • Listen APIs return EMPTY; connect/emit are no-ops on the server.
  • Prefer autoConnect: false when the URL depends on client-only state.
  • DestroyRef cleans up listeners when the owning injector is destroyed.

13. Testing (ngxsmk-socket-io/testing)

Replace the real client factory with mocks so unit tests never open network sockets.

  • createMockSocketFactory() — returns factory, state, and latest().
  • Provide { provide: SOCKET_IO_CLIENT_FACTORY, useValue: factory } alongside provideSocketIo.
  • Drive inbound events with latest().emit('message', payload) (mock socket).
